# wake_capture 测试指南（唤醒抓拍周期：睡眠→抓拍→相机下电→SD/HTTP→再睡→空闲）

配套固件：功耗测试固件（CUSTOMER_ID=11/POWER_TEST_DEMO）2026-10-22 14:55 构建，APP.bin 1,043,984 字节，MD5 `dc5a47a96f971ca700903bda65fd26ee`（存档 `archive/20261022_145512/`）。本组件与 app_power_test 的同步休眠封装（`pt_sleep_sync`）同版交付，指南同时覆盖 `AT+PWRS`/`AT+PWRDT` 走封装后的回归。

测试目的：验证"唤醒即抓拍"的产品形态闭环——停泊中被任意源唤醒（定时兜底/远程数据包）→ 抓 1 张 1080p JPEG 暂存 PSRAM → **相机轨立即下电** → 按配置落 SD 卡和/或 HTTP 上传 → 立刻再睡 → 下次唤醒空闲；RTCC 路径验证冷启动抓拍（重启唤醒，boot 期消费 KV 意图）。同时采集各段耗时（抓拍窗口、SD 腿、HTTP 腿、清醒窗口总长）作为产品时序/功耗基线。

## 1. 硬件与接线

- 串口：调试烧录/串口测试点 ↔ USB 转串口，**921600-8-N-1**（COM7）。
- **TF 卡**：插卡（FAT32/exFAT 均可，SDK fatfs 支持）。不插卡时 SD 腿优雅失败不影响其余流程。
- **相机**：GC20C3 模组已在板（勿动 FPC）。
- **HTTP 接收端**：测试 PC 与板同一路由（板 IP 形如 192.168.110.4）。
- 功耗测试（可选）：电流表串入供电回路；周期内 LED 全程熄灭（`pt_led_hold`），不会引入额外电流。

## 2. 烧录

```bat
custom\tools\burn.bat        # CKLink；连不上目标时先串口发 AT+RST 软复位再试
```

烧完自动复位运行。注意：**RTCC 停泊/重启周期后 CKLink 可能失联（正常现象），串口发 `AT+RST` 即可恢复**（2026-10-22 验证）。

## 3. 上电预期

上电 ~4s 后串口横幅（节选）：

```
PT: boot wake reason=...            # 复位型唤醒原因，仅开机可读
WC: wake-capture test ready. AT+PWCAP=<0..3>,<secs>[,<skip>[,<type 1|3|5>]] ...
PT: power test demo ready. AT+PWR? for status, AT+PWRS=<type 1..5>,<secs> to sleep (synchronous), ...
```

LED 1Hz 闪 = 清醒待机；**PWCAP 周期内全灭**。WiFi 按 syscfg 凭据自动关联（`AT+PWR?` 看 `ip=`）。若上一次 RTCC 意图未消费（异常断电），开机横幅会多一行 `WC: pending RTCC capture intent found -> cold-boot capture cycle` 并自动跑一次冷启动抓拍；不需要时 `AT+PWCAP=0` 解除。

## 4. 串口 AT 指令（本组件）

| 指令 | 作用 |
|---|---|
| `AT+PWCAP=<mode 0..3>,<secs 5..3600>[,<skip 0..10>[,<type 1\|3\|5>]]` | 跑一个唤醒抓拍周期。mode：1=存SD 2=HTTP上传 3=两者 0=**解除挂起的 RTCC 意图**；secs=两段停泊的 RC 兜底窗口；skip=AE 跳帧（默认 3，写入文件名）；type 1=SRAM_WIFI 断点续跑（默认，可被数据包提前唤醒）、**3=SRAM_ONLY（无 WiFi 保活值班——仅存 SD 低功耗场景，无远程唤醒）**、5=RTCC 重启冷启动 |
| `AT+PWCAP?` | busy/配置/RTCC 意图状态 + 上次周期报告（RTCC 重启后 RAM 报告丢失，看串口日志） |
| `AT+PWCURL=<url>` | HTTP 上传目标 `http://<ip\|host>[:port]/path`（RAM 保存，重启回默认；RTCC 路径随意图一起入 KV） |

配套（app_power_test，详见其 README）：`AT+PWRS`/`AT+PWRDT`（与本组件互斥）、`AT+PWRLOG=<0..7>`（打印级别，排障用）、`AT+PWR?`、`AT+PWRLED/PWRDBG/PWRHK`。

互斥：同窗口只允许一个 park——PWRS/PWRDT 运行时 PWCAP 拒绝，反之亦然。

## 5. PC 侧接收端（HTTP 腿用）

```bash
python custom/tools/http_recv.py [port]     # 默认 8080，绑 0.0.0.0
```

每收一个 POST 存 `custom/tools/wc_recv/WC_时间戳.jpg` 并打印大小与 JPEG SOI 校验。先确认 PC 的局域网 IP（如 192.168.110.5），板上 `AT+PWCURL=http://<该IP>:8080/upload`。Windows 首次可能弹防火墙授权，允许即可（2026-10-22 实测未拦）。

## 6. 测试流程

### 6.1 SD 存卡冒烟（~40s，需插卡）

```
AT+PWCAP=1,10
```

预期（实测基线 2026-10-22）：

```
WC: cycle mode=1(sd) secs=10s ...
WC: wake#1 rsn=1 +184ms - capture window        # 唤醒=RC 定时，唤醒→开抓 184ms
NE102: capture track up ... (1920x1080)
WC: capture rc=0 53432B in 457ms - camera dark  # 抓拍+相机下电 <0.5s
WC: sd saved 0:/DCIM/WK_00x.JPG (53432B crc ok) # 写卡+读回 CRC 校验通过
WC: sd ok in 280ms (mount..verify..unmount)
WC: cycle done: ... sd rc=0 280ms ... awake=1105ms   # 清醒窗口 ~1.1s
```

拔卡上 PC 可直接查看 `DCIM/WK_00x.JPG`（1080p JPEG）。连跑 3 轮文件名递增（重启后计数归零会覆盖同名，测试件行为）。

### 6.2 HTTP 上传（~40s，需接收端）

```
python custom/tools/http_recv.py            # PC 侧先起
AT+PWCURL=http://<PC_IP>:8080/upload
AT+PWCAP=2,10
```

预期：`WC: http status=200 sent=~47000B in 350ms`，PC 端打印收到 ~47KB、SOI yes，`wc_recv/` 落盘文件可打开。无网/接收端未起时该腿快速失败（connect 6s 上界），周期照常走完。

### 6.3 双落盘 + 无卡降级（~40s）

```
AT+PWCAP=3,10
```

预期：SD 腿与 HTTP 腿依次执行（相机均已下电），`sd rc=0 ... http=200`。**拔掉 TF 卡再跑一次**：`sd open ... err=` 记日志后继续，HTTP 不受影响（PRD 红线：存储失败不阻塞）。

### 6.4 远程数据包提前唤醒（产品场景，可选）

`AT+PWCAP=2,60`（60s 窗口）后在停泊期内向板 IP 发一个带载荷的 TCP 包：设备应**提前唤醒**并照常抓拍上传，报告 `wake1=<remote-data 系原因>`、清醒窗口同量级。

### 6.5 RTCC 冷启动路径（~40s）

```
AT+PWCAP=1,8,,5
```

时序：`RTCC arm: intent saved (KV), parking RTCC 8s` → 设备停泊 → **8s 后重启（冷启动，串口工具会闪断重连一次，属正常）** → 新开机日志：

```
PT: boot wake reason=1(timer)
WC: pending RTCC capture intent found -> cold-boot capture cycle   # +102ms 检出
WC: cold-boot capture: ... | boot rsn=1 +105ms
NE102: capture track up @201ms (1920x1080)        # +201ms 管线起
NE102: stashed frame #1 @477ms                    # +477ms 照片暂存
WC: boot cycle done: ... | boot->report=...
WC: re-sleep RTCC 8s - next boot is IDLE          # 再睡；再下次开机无意图=空闲
```

判读三点：① boot 期检出意图行存在；② boot→照片暂存 ~0.5s；③ 第二次开机**没有**意图检出行（one-shot 语义）。改 mode=2/3 可测冷启动上传（HTTP 腿会先有界等 IP ≤15s）。

### 6.6 同步封装回归（改固件后必跑）

```
AT+PWRS=1,10      # 预期 wake #N sr=0 wait=ok，dur err≈0ms
AT+PWRDT=10       # 预期 dtim exit_by=rc-verdict，err≈+260ms，resume exit->cb≈179ms
```

### 6.7 自动全套（等串口空闲自动跑）

```bash
python custom/tools/wc_test1.py     # 等 COM7 释放→PWRS/PWRDT 回归+PWCAP 1/2/3+RTCC 腿，自动拉接收端
python custom/tools/wc_rtcc.py      # 单独重跑 RTCC 腿（抗串口闪断）
```

日志：`custom/tools/wc_test1.log` / `wc_rtcc.log`。

## 7. 判定要点（2026-10-22 板测基线）

| 指标 | 基线 | 判定 |
|---|---|---|
| 唤醒→开抓 | 184ms（sleepcb RESUME 后） | 稳定即正常 |
| 抓拍窗口（含相机下电） | 457~462ms，~53KB 1080p | >1s 查 AE 跳帧/光照 |
| SD 腿（挂载..读回CRC..卸载） | 280~310ms | crc ok 必须出现 |
| HTTP 腿 | 130~350ms（首连 350ms） | status=200 |
| SRAM 清醒窗口总长 | ~1.0~1.2s | 含两段 park 切换 |
| RTCC boot→照片暂存 | 477ms | 冷启动链路健康 |
| 唤醒原因 wake1 | 定时兜底=1(timer)；远程包=remote-data 系 | 仅供参考，非权威 |
| awake 总时长 | jiffies 基（停泊冻结），只计清醒时间 | 勿当墙钟 |

- **one-shot**：任何一次 PWCAP 只抓一次；第二段停泊唤醒/第二次开机必为空闲（无 WC 周期日志）。
- **功耗形态**：相机只在抓拍窗口带电（`camera dark` 打印点之前）；SD/网络 IO 全部在其后；TF 在再睡断轨前已卸载。
- 首轮 SD 周期一条 `sd0 mount fail ret=-16(EBUSY)` 为 hotplug 异步挂载与直接挂载的竞争噪音（其一成功即可），后续周期不出现。

## 8. 故障排查

| 现象 | 首查 |
|---|---|
| `capture rc=-1 0B`，日志刷 `SID: ff,...` | sensor 探测失败：确认 power_test_config.h `DEV_SENSOR_GC20C3=1` 且 GC2053=0（本板曾配错，见 PROJECT_STATUS 10-22 根因③） |
| 周期中途看门狗复位（`soft_reset`） | PSRAM 池超限断言：确认 `CONFIG_PSRAM_AVHEAP_SIZE=4MB`（根因①） |
| `intent KV write failed` | `flashdb_init` 未调/失败（根因②，当前版本已在 init 补调）；看 KV 分区 0x7F0000 是否被占 |
| `sd open ... err=12` 反复 | 卡未插/接触；`AT+PWRLOG=7` 后重跑看 sdhost 探测序列（ocr/scr 出现=卡好，挂载层问题对照根因④） |
| `sd write err=0` | 旧版 fwrite 判断 bug（根因⑤），现版本已修；复现则查 osal_file 返回语义 |
| HTTP connect 超时 | PC 接收端未起/IP 配错/防火墙；板侧 6s 上界后继续 |
| RTCC 后串口工具掉线 | 板电波动致 CH340 闪断，属正常，重连即可；脚本已自动处理 |
| RTCC 后 CKLink 烧不进 | 串口 `AT+RST` 软复位后重试 burn.bat |
| AT 全程无响应 | 板在停泊中（RC 兜底 secs 内必醒）；或已重启——重开串口工具 |

## 9. 已知边界

- RTCC 路径报告只在串口日志（再睡重启抹 RAM），`AT+PWCAP?` 查不到。
- arm 后、RTCC 到点前手动断电，下次开机仍会执行一次冷启动抓拍；`AT+PWCAP=0` 解除。
- 文件名 `WK_%03u` 计数 RAM 保存，重启归零覆盖同名（测试件）。
- URL 仅 http、无鉴权；host 走 DNS 受 lwip 超时影响，建议直接填 IP。
- 停泊期对板发 TCP 数据包可提前唤醒（6.4），但过滤为"带载荷即醒"，未做命令解析——协议化 WK_DATA 属产品 ④ 期工作。
